# loglens

[English](README.md) | [Русский](README.ru.md)

Скилл и CLI, которые ставят диагноз огромному логу без построчного чтения.

Лог на 500 МБ нельзя прочитать — ни человеком, ни агентом с конечным контекстом. Но логи повторяются: нормализуй переменные части, и 3000 почти одинаковых строк схлопнутся в несколько шаблонов со счётчиками, диапазонами строк и одним настоящим образцом. `loglens` читает файл стримingly (в памяти — только шаблоны), кластеризует, считает уровни и показывает, когда проблемы всплесками:

```text
$ loglens scan app.log
lines    3,000 (222,367 bytes)
time     2026-10-30 09:00:00 … 2026-10-30 10:39:58
levels   INFO 1,999, DEBUG 579, WARNING 273, ERROR 149

  149×  L902-L1050  [ERROR]
        2026-10-30 09:30:02 ERROR api.db timeout after 30s query=select * from lots where id=491
```

## Что в репозитории

- **[skills/log-triage](skills/log-triage)** — порядок чтения для агентов: счётчики уровней → топ шаблонов ошибок → по одному образцу → ограниченное чтение вокруг инцидента. Сравнение периодов, группировка по полям, подтверждение фикса повторным сканом.
- **tools/loglens** — CLI ([README](tools/loglens/README.md)): `scan` (кластеризация в шаблоны), `spikes` (временные бакеты проблем), `demo` (синтетический лог с подсаженным инцидентом). Стриминг, `--json`, только stdlib.

## Установка

```bash
pip install loglens
npx skills add juzorei/loglens
```

## Рамки

Работай с логами, которыми владеешь или имеешь право читать. В логах часто данные пользователей — цитируй минимум в отчётах.
